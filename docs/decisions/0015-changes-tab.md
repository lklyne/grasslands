# 0015: Git footer and the Changes tab

- **Parent branch** is the repo's default branch: the local branch `origin/HEAD` names, else `main`, else `master`. On the default branch itself it is the upstream. No guessing from reflogs or the nearest branch: a branch cut from this one sits at the same commit and would look like the parent.
- **The diff runs from the merge base to the working tree**, untracked files included, so the footer and the tab show what the branch's PR would hold plus anything not yet committed. Renames count as a deletion and an addition. Read on the background executor; the footer at most once a second, the tab every 3 s while open, redrawn only when the patch text changed so scrolling keeps its place.
- **One implementation: git itself.** `crate::fs::git` holds the rules as shell scripts run with the machine's git, on this Mac (`fs::local::run`) and on a saved machine (over its SSH master, 0020) alike. Untracked files count through a copy of the index where they are intent-to-add. Local used git2 until 2026-10-18; a parity test over fixture repos (no upstream, upstream ahead and behind, gone upstream, `origin/HEAD` vs `main` vs `master`, detached, unborn, unrelated histories, staged/unstaged/deleted/untracked/binary/mode/rename changes, odd file names, a linked worktree and its main checkout, subfolders) matched git2's summary, patch, branch, ahead/behind, placement and root exactly before the switch, and now checks those reads against fixed expectations (`fs/git_tests.rs`). Patches differ only in spelling the diff parser reads alike: git ends a path holding a space with a tab and, with `core.quotePath=false`, prints non-ASCII paths unquoted.
- **The scripts write nothing in the repo.** The file tree watches the worktree, `.git` included, and re-reads git on any change, so a write would loop. The copied index keeps its time (`cp -p`; a fresh copy made racily clean entries look clean, missing a same-size edit made in the same second as the last index write), the empty blob `add -N` writes (or freshens, every run) goes to a temp object store, and fsmonitor is off for these commands, since its daemon writes cookie files in `.git`. A test checks `.git` is untouched.
- **Cost.** On this repo (about 1,800 files) a summary read takes about 115 ms and a patch read about 150 ms, against about 48 ms for git2: each git process costs 6-8 ms to start and the script starts seven. All of it runs off the UI thread and at most once a second, so it was kept rather than leaving git2 on Local's hot path. The script starts as few processes as the rules allow (one `for-each-ref` for the branches the rules look at, one `diff --raw --numstat` for the summary). Larger repos weren't measured from this worktree; the diff itself dominates there and costs git2 the same.
- **Finding git.** An app opened from Finder gets launchd's minimal `PATH`; `main` puts Homebrew's and the other usual install folders first inside a bundle, so `git` is found where a terminal finds it. `/usr/bin/git` is a stub that offers to install the Command Line Tools until they are, so it counts only when `xcode-select -p` succeeds (`fs::local::has_git`, checked once). With no git, Local shows no git info, as outside a repo.
- **One Changes tab**, after the file tabs, following the active worktree, rather than one per worktree or a tab kind inside the editor: the editor's tabs are file buffers throughout, and a single live view of "what this worktree changed" is the useful thing.
- **Lines wrap** (`Diff::soft_wrap`); no horizontal scrolling. The diff notifies its own state after a paint once it knows the width, so `Changes` observes it and redraws; without that the wrapped rows stay at zero width and the tab is blank.
- **gpui-component is vendored** (`vendor/gpui-component`, see its PATCHES.md) to give the diff's list overdraw. Without it the wheel can only reach the last painted row: GPUI's list drops the diff's row-height hint whenever its width changes, so rows below the viewport count as 0 px. Drop the vendor copy once GPUI Kit fixes this.
