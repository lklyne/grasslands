# 0002 herdr 0.9.5: the spec's known API gaps still exist

Checked against `docs/herdr-api-0.9.5.schema.json` and herdr.dev/docs/socket-api on 2026-10-15.

## Plugin popup placements: still invisible to us

`PluginPanePlacement` is `overlay | popup | split | tab | zoomed`. The socket docs say a popup "has no pane ID, stays outside all `pane.*` and agent APIs, and emits no pane lifecycle events", and does not get `HERDR_PANE_ID`. The only popup call is `popup.close` (`popup_not_open` when none is open). There is no terminal id to attach to, so we can't show popups. `split`, `tab`, `zoomed` and `overlay` create real panes and show up through the normal events.

Partial workaround: `plugin.pane.open` takes `placement` from the caller, so when the app opens a plugin pane itself it can ask for `overlay` or `zoomed` instead of `popup` and get a real pane. Popups that a plugin's own action command opens stay invisible to us. Feature request to file: give popups a pane/terminal id and lifecycle events, or a placement hint clients can override.

## `herdr notification show`: still no event

`notification.show` is a request (result `notification_show` with `shown` and `reason`: `shown | disabled | rate_limited | no_foreground_client | busy`). No `EventKind` or `Subscription` type covers notifications, so we can't see toasts other tools send. With `ui.toast.delivery = "system"` they at least reach the OS. Feature request to file: a `notification.shown` subscription carrying title/body/source.

## Related, found while building the client

- `pane.agent_status_changed` can only be subscribed per pane (see 0001). An all-panes form would remove the resubscribe dance. Worth a feature request.
- No event when a pane's `cwd`/`foreground_cwd` changes (checked: `cd` in a
  pane produces no event; `pane.get` shows the new folder). The app polls the
  focused pane with `pane.get` every 2 s (`AppState::poll_focused_dir`) so the
  active worktree follows `cd` and agents changing folder. Feature request:
  emit `pane.updated` (or a `pane.cwd_changed`) when the foreground cwd changes.

## Remote machines (0019)

Checked against herdr 0.9.5 and the `dockerbox` test machine on 2026-10-18.

- No machine events: nothing on the socket says a machine was added,
  renamed, enabled, disabled or removed, and `session.snapshot` has no
  machines. The app polls `herdr machine list --json` every 30 s (and after
  its own add). Feature request: `machine.*` events, or machines in the
  snapshot.
- `herdr machine status --json` gives `{id, label, status, error}` only, not
  the remote herdr binary or its server's socket, so the app still finds
  both itself over SSH. Feature request: add them.
- Surface interest (`client_shell.surface.set`) answers
  `connection_local_only` to an API client, so a socket client can't stop an
  unselected machine's terminals from streaming except by detaching them.
- Nothing over the API says which client holds a terminal's direct attach.
  A refused attach and a taken-over one both just exit 1, so the app can
  only say "Detached".
