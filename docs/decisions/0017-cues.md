# 0017: Interface and status sounds (cues)

- **A port, not a library call.** `crates/cues` ports
  [cuelume](https://github.com/danielwh2/cuelume) (MIT) at commit `2a1ba4f`:
  the same fourteen cues, recipes and themes, synthesized at play time with
  no audio files. `crates/cues/AGENTS.md` is the usage guide. To move to a
  newer cuelume, re-port against its diff and regenerate the references.
- **Parity tests.** `scripts/cues-refs` runs cuelume's own offline renderer
  (`sound.mjs`) over every theme, cue, emphasis, part and walk step into
  `target/cues-refs`; `tests/corpus.rs` requires our `render` to match each
  file to within 100 dB of residual. `tests/plugin.rs` checks the WAVs
  cuelume ships for its Claude Code plugin to 85 dB after the same 16-bit
  quantising.
- **Mixer.** `Cues` only queues commands on a channel, so playing never
  blocks. A worker thread makes cuelume's decisions (cadence, the walk, held
  presses, one voice per cue), renders at the device's rate, and hands whole
  voices to the cpal callback over a bounded `std::sync::mpsc` channel. The
  callback keeps 64 preallocated slots, never locks, allocates or frees, and
  hands spent voices back to be dropped on the worker. The stream opens on
  the first play (48 kHz f32 preferred), pauses after 2 s of silence, and
  reopens after a fatal error; with no device everything is a silent no-op,
  logged once. `play` renders press and release as one voice, as cuelume
  does.
- **Handoff approximation.** When a cue plays again its last voice fades
  exponentially over 80 ms (400 ms for note cues) to 1e-4 of its own level.
  cuelume fades the voice's absolute gain (recipe gain × volume) to 1e-4;
  the mixer never sees the recipe gain, so the curve's slope differs
  slightly. Both end inaudible.
- **Settings.** Settings → Sounds: a Sound on/off switch, a theme (Default,
  Mech, Bubble, Press) and a volume, saved in
  `~/.config/grasslands/settings.json` as
  `"sounds": { "enabled": true, "theme": "default", "volume": 1.0 }`
  through the same helpers as the theme keys (decision 0014). An older
  `"theme": "off"` reads as off. Turning sound on plays a `Toggle`, picking
  a theme previews `Ready` then `Attention`, and changing the volume plays
  a `Tap`. Agent status sounds (`Attention` when blocked, `Ready` when done)
  replace the AppKit system sounds, which remain only as the fallback when
  the cues worker can't start. Which agent changes sound at all follows
  herdr's config (decision 0021).
- **Optimized in dev.** Every play is synthesized, and unoptimized that
  takes ~50 ms for a `Tap`, too slow for interface cues. The workspace sets
  `[profile.dev.package.cues] opt-level = 3`, so dev builds render in 2–5 ms
  (`Count`, the longest cue, ~10 ms) like release. The noise and room
  spectra are cached per rate and convolution size.
